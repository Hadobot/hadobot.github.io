Route All Your Internet Traffic Securely Through Your Raspberry Pi Using Tailscale Exit Nodes

Dec 26, 2025
4 minute read

In my previous article, Access Your Home Router from Anywhere Using Tailscale and a Raspberry Pi, I showed how to set up subnet routing so that your remote devices can access your home LAN, including your router, as if you were physically at home. That setup works perfectly for accessing local devices, but what if you want all your internet traffic to exit through your home network securely, while connected from anywhere in the world?

This is exactly what a Tailscale Exit Node allows you to do. Using the same Raspberry Pi from the first setup, you can route all traffic through your home network, giving you the security and consistency of your home ISP while on mobile networks or public Wi-Fi.

By the end of this guide, your Raspberry Pi will serve two purposes:

  • Forward traffic to LAN devices (subnet routing)
  • Route all internet traffic securely (exit node)

Step 1: Understand Tailscale Exit Nodes

A Tailscale Exit Node acts as a gateway for your remote devices:

  • Traffic from your mobile or laptop flows through the Tailscale mesh
  • The Raspberry Pi forwards all internet traffic to your home network
  • Services on the internet see your home public IP, not the network you are physically on
  • Subnet routing and LAN access continue to function simultaneously

In essence, your device behaves exactly like it’s at home, no matter where you are.

Step 2: Prepare Your Raspberry Pi

You don’t need to redo the Tailscale setup from the previous article. Make sure:

  • The Raspberry Pi is connected via Ethernet for stable routing
  • Tailscale is installed and logged in
  • Subnet routing (192.168.1.0/24) is already enabled

For reference, here’s the system we used:

  • Raspberry Pi 3
  • Latest Desktop version of Raspberry Pi OS
  • Mobile device tested: Android
  • Home LAN subnet: 192.168.1.0/24

Step 3: Enable the Exit Node

To advertise your Pi as an exit node, run the following command on your Raspberry Pi:

sudo tailscale up \
  --advertise-routes=192.168.1.0/24 \
  --advertise-exit-node \
  --accept-routes \
  --ssh

What Each Command Does

  • --advertise-routes=192.168.1.0/24 keeps your LAN devices accessible
  • --advertise-exit-node tells Tailscale to allow your Pi to act as a full internet gateway
  • --accept-routes ensures the Pi can forward the routes it advertises
  • --ssh allows SSH access via Tailscale

No reinstallation is needed — you’re just extending your existing setup.

Step 4: Approve the Exit Node in Tailscale Admin Console

  1. Go to Tailscale Admin Machines
  2. Select your Raspberry Pi
  3. Enable Advertised Routes (if not already approved)
  4. Enable Exit Node

After approval, the Pi is ready to route all traffic for any authorized device in your tailnet.

Step 5: Test the Exit Node

From your mobile device:

  1. Disconnect from home Wi-Fi, stay on mobile data
  2. Connect to Tailscale
  3. Select the Raspberry Pi as your Exit Node and enable “Route all traffic”

Test the behavior:

  • Access your router (192.168.1.1) — it should still load with your router admin page
  • Check public IP using https://ifconfig.me — you should see your home network’s public IP (e.g., 61.xxx.xxx.xxx)

Observations from my setup:

  • Latency for web browsing was minimal
  • Router and NAS devices on the LAN were fully accessible
  • Toggling the exit node on/off correctly switched the public IP between mobile and home IP
  • HTTP traffic, streaming, and downloads functioned normally

This confirms that your Raspberry Pi now acts as a dual-purpose router and exit node.

Step 6: Optional Enhancements

Once the exit node is stable, you can consider:

  • Adding ACLs to restrict which devices can use the exit node
  • Multiple exit nodes for redundancy
  • Integration with a commercial VPN for added privacy, while keeping Tailscale routing

These enhancements will be covered in future articles.

Conclusion

By combining subnet routing with an exit node, your Raspberry Pi now provides:

  • Full access to your home LAN devices from anywhere
  • Secure routing of all internet traffic through your home network
  • A foundation for advanced setups, like commercial VPN integration

This builds directly on the setup described in my previous article. You now have a fully functional remote gateway that behaves exactly like being on your home network — a powerful tool for secure remote access.
