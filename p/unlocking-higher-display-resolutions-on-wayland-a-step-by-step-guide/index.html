Unlocking Higher Display Resolutions on Wayland: A Step-by-Step Guide

Oct 03, 2025
4 minute read

If you’ve followed the previous article on using xrandr to unlock higher resolutions on Xorg-based systems, you might have wondered: what about Wayland? Wayland, the modern display server protocol replacing Xorg on most Linux distributions, handles displays quite differently. It’s faster, more secure, and avoids some legacy issues — but also removes tools like xrandr, which means custom resolutions require a different approach.

In this guide, we’ll explore how to achieve higher or custom resolutions on Wayland-based systems using kernel parameters and EDID overrides. By the end, you’ll be able to force a resolution like 1920x1080 even when your laptop or monitor doesn’t advertise it.

Step 1: Check Whether You’re Running Wayland or Xorg

Before doing anything else, verify that your current session uses Wayland:

1

echo $XDG_SESSION_TYPE

If the output is wayland, continue with this guide. If it says x11, your system is running Xorg, and you can follow the previous xrandr method instead.

Step 2: Understand the Difference Between Wayland and Xorg

Under Xorg, users could freely add or remove display modes using xrandr. Wayland, however, delegates resolution management to the compositor (e.g., GNOME Shell, KDE Plasma, Sway). This design increases stability but means you cannot directly inject custom resolutions at runtime.

Instead, you must:

  1. Instruct the kernel to pretend the display supports your desired resolution, or
  2. Provide a custom EDID (Extended Display Identification Data) file that includes your desired mode.

Step 3: Determine Your Display Output Name

Each display output is represented under /sys/class/drm. To find your active display:

1

ls /sys/class/drm/*/status

Then check which outputs are marked as connected. For example, you might see:

1

/sys/class/drm/card0-eDP-1/status: connected

In this case, your output name is eDP-1.

Step 4: Force a Resolution Using a Kernel Parameter

If your monitor supports the new resolution but your system doesn’t expose it, the easiest method is adding a kernel parameter to force it.

  1. Open your boot configuration file (for example, on Ubuntu or Debian):

    1

    sudo nano /etc/default/grub

  2. Find the line that starts with:

    1

    GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"

    and append your video mode, for example:

    1

    GRUB_CMDLINE_LINUX_DEFAULT="quiet splash video=eDP-1:1920x1080@60"

  3. Update GRUB and reboot:

    1
2

    sudo update-grub
sudo reboot

After rebooting, open your display settings (GNOME Settings → Displays or KDE System Settings → Display & Monitor) and select 1920x1080.

Step 5: Using a Custom EDID (Advanced Method)

If the kernel parameter method fails — often the case with certain laptops or NVIDIA drivers — you can create a custom EDID file to trick the system into recognizing the resolution.

  1. Generate an EDID file using a tool such as edid-decode or wxEDID, or start from a known-good one.

  2. Save your custom file under:

    1
2

    sudo mkdir -p /lib/firmware/edid
sudo cp 1920x1080.bin /lib/firmware/edid/

  3. Edit your GRUB configuration again and add:

    1

    drm.edid_firmware=eDP-1:edid/1920x1080.bin

  4. Update GRUB and rebuild the initramfs (important for persistence):

    1
2
3

    sudo update-grub
sudo update-initramfs -u
sudo reboot

After rebooting, check your available resolutions in your compositor’s display settings. The new resolution should now appear.

Step 6: Select the New Resolution

Once the kernel or compositor recognizes your forced mode, you can select it:

  • GNOME (Wayland): Open Settings → Displays and choose the resolution manually.

  • KDE Plasma (Wayland): Use the GUI under System Settings → Display and Monitor, or use the CLI:

    1
2

    kscreen-doctor --outputs
kscreen-doctor output.<ID>.mode.<MODE>

If you don’t see your resolution, double-check the boot parameters and verify using:

1

dmesg | grep -i drm

to confirm the kernel applied the EDID or video mode correctly.

Step 7: Persisting the Configuration

Unlike Xorg, Wayland doesn’t execute ~/.profile on login for display modes. Persistence must come from:

  • GRUB configuration (kernel parameters), or
  • EDID injection (firmware-level override).

Once configured, your system will boot with the desired resolution every time.

What’s Next?

You’ve now learned how to unlock custom resolutions on both Xorg and Wayland systems. While Wayland requires a bit more setup, these methods ensure your system boots with the exact resolution you want — no matter what display you’re using.
