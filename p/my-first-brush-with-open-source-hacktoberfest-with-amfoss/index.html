My First Brush with Open Source: Hacktoberfest with AMFOSS

Sep 15, 2025
4 minute read

Hacktoberfest with AMFOSS

A while back, I attended a Hacktoberfest event conducted by AMFOSS at my college. At that time, I didn’t fully realize how important that experience would be for shaping my understanding of open source, collaboration, and software development as a whole. Looking back now, it feels less like a workshop and more like an introduction to a mindset.

Session 1: Understanding Open Source Beyond Code

The first session eased us into the idea of open source not just as code available on GitHub, but as a global collaboration built on trust, learning, and shared ownership.

We were introduced to organizations like Kolibri, which highlighted how open source can directly impact education and accessibility. This was also where I first heard deeper discussions around large-scale open-source infrastructure, like Docker containers and Kubernetes, and how they’re used in real-world projects.

Programs such as GSoC (Google Summer of Code) and LFX Mentorship were discussed, opening up the idea that contributing to open source could also lead to structured mentorships and even remote internships. Until then, I had mostly seen open source as something “advanced developers” did. This session quietly broke that myth.

We also looked at real projects: names like Worm, INCF, and Growing Graph Neural Networks and how contributors collaborate through Slack and Discord, follow contribution guidelines, and stay connected through community channels.

But what stood out the most was the honest discussion about challenges like:

  • Imposter syndrome is real, and almost everyone feels it.
  • Even the smallest contribution counts.
  • Large tasks become manageable when broken down step by step.
  • Understanding a codebase often starts with reading existing pull requests.
  • Asking for help is not weakness, even if the question feels “dumb”.

There was a strong emphasis on reading documentation, handling feedback maturely, and always respecting the code of conduct and community etiquette. Consistency mattered more than intensity. Stay curious. Keep learning. Keep showing up.

Session 2: Making Sense of Git and GitHub

The second session focused on the backbone of modern software development: Git and GitHub.

We started with the basics Git as a distributed version control system, and why it’s almost a requirement for any software developer today. The idea that Git stores snapshots of a project over time, rather than just files, helped me understand version control more clearly.

Concepts like:

  • Working directory, Git directory, and remote repositories
  • Commits and branching as independent environments
  • Forking vs cloning, and how pull requests fit into collaboration
  • Merge conflicts and code reviews

suddenly felt less intimidating when explained through real workflows.

We were also introduced to CI/CD, where tools like GitHub Actions automatically test and validate code, reinforcing the idea that quality and automation go hand in hand in professional projects. The mention of Git’s robust security and collaborative review process made it clear why it’s trusted at scale.

Practical resources were shared too—like the GitHub Student Developer Pack and interactive platforms such as learngitbranching, which encouraged hands-on learning rather than passive listening.

Sessions 3 & 4: Learning by Doing

The later sessions leaned into practice and experimentation. Initiatives like r/place and amplace were used as playful yet effective ways to learn GitHub collaboration in action. These weren’t just exercises, they were reminders that learning doesn’t always have to be rigid to be effective.

There was also a brief introduction to the Wikimedia movement, reinforcing the broader philosophy behind open source: collective knowledge, maintained by people who care enough to contribute.

Looking Back

At the time, I walked away with pages of notes and a head full of concepts. Today, what stays with me is something simpler: the realization that open source is less about being an expert and more about being willing to learn in public.

That Hacktoberfest event didn’t instantly turn me into an open-source contributor—but it gave me clarity. It showed me that progress comes from consistency, curiosity, and the courage to start small.

Much like this blog, the journey isn’t about perfection. It’s about showing up, learning from feedback, and slowly building confidence, one contribution at a time.
